# 声见 · Pitch Studio

本机运行的实时人声调音与声音可视化工具。React + TypeScript + Vite + Web Audio + Canvas 2D；无需账号、后端或云端音频服务。

## 开始使用

需要 Node.js 22.12+，推荐使用当前 Node.js LTS。此工作区已安装依赖。

```powershell
npm ci
npm run dev
```

打开 <http://127.0.0.1:5173/>，点击「开启麦克风」并允许访问。Windows 也可以双击 `启动声见.cmd`。如果网页已经运行，直接打开上面的地址即可。

开发服务固定使用 5173 端口，不会自动换端口。端口被占用时，请检查是否已经启动了本项目。

```powershell
npm run build
npm run preview
```

生产预览地址为 <http://127.0.0.1:4173/>。`dist/` 可以部署到任意支持 HTTPS 的静态网站服务；本项目没有自动部署到互联网。普通局域网 HTTP 地址通常无法取得麦克风权限。

## 功能

- 实时音名、Hz、音分偏差、输入电平、最近 10 秒音高曲线。曲线纵轴自动容纳整段轨迹与目标音，大跨度滑音也不会被裁掉。
- **频谱图**：50–8000 Hz 对数坐标，多个独立频率峰值，以及可靠音高对应的谐波参考线。
- **声谱图**：最近 10 秒的时间／频率热图，标有强度色尺；采集或浏览器暂停造成的缺口保留为空白。
- **波形图**：正向过零触发，5／10／20／50 ms 窗口，1／2／4／8 倍显示放大。高采样率下仅提供当前样本能够完整覆盖的窗口。振幅坐标随显示放大变化，悬停始终显示原始采样值。
- **冻结画面**：保留三个分析图及音高轨迹的快照，麦克风、当前音高读数继续更新；恢复后回到最近的实时数据。
- **参考钢琴**：C2–C7，A4 = 440 Hz；合成参考音。选定琴键成为比较目标，清除目标后重新比较最近的半音。目标音与检测音用不同颜色标示。
- 麦克风选择、授权等待与取消、错误重试、断开提示；停止后释放麦克风，保留最后的分析画面。
- 中文深色界面、窄屏适配、键盘可操作页签与琴键。

建议佩戴耳机试听参考音。麦克风不会直接回放，但外放参考音仍可能从空气进入麦克风。参考音不直接接入分析图。

## 分析与数据边界

- `src/audio/session.ts` 维护一个采集会话，两条独立分析支路：4096 点时域分析用于音高，8192 点 FFT 用于频谱。
- `src/audio/analysis.ts` 使用 Pitchy 的 McLeod Pitch Method 估计基频；音高需要至少 −60 dBFS RMS 与 0.9 的清晰度。频谱峰值独立计算，不把最强峰直接当作基频。FFT 由浏览器完成。
- 以实际 `AudioContext.sampleRate` 计算坐标和频率。约 30 次／秒采样更新，不承诺硬件无关的固定端到端延迟。44.1 kHz 下频谱 bin 间隔约 5.38 Hz，48 kHz 下约 5.86 Hz。
- 使用真实经过时间定位历史；滚动历史保留 10 秒并有 360 帧上限。冻结额外保留一份有界快照。音频样本仅短暂留在页面内存中，不写入浏览器存储，不生成录音文件，不上传。
- 频谱强度是数字信号的相对 dB，RMS 电平以 dBFS 表示，均不是经过声学校准的 dB SPL。
- 请求关闭回声消除、降噪和自动增益，并在「采集状态」展示 `getSettings()` 实际报告值。浏览器未报告的值明确标记为「未报告」；不能保证声卡或麦克风固件完全不处理声音。
- 面向单人说话或唱歌。频谱可同时显示多个频率成分，但音名检测不提供多声部识别。无可靠基频时音名留空，声音图表仍正常展示。

## 验证

```powershell
npm test
npm run test:browser
npm run test:soak
```

- **单元测试**：44.1／48 kHz 下 65.406、110、220、440、880、2093 Hz 的误差小于 5 音分；二次谐波更强；静音、低电平与确定性白噪声；频谱定位、音名映射、历史裁剪和波形触发。
- **浏览器测试**：使用本机已安装的 Chrome 和 Edge。测试专用的合成输入接入真实 Web Audio 分析链路；生产页面没有假数据模式或麦克风绕过代码。覆盖三个图表、冻结、钢琴、麦克风错误、取消等待、反复启停、断开及音频上下文暂停。
- **持续测试**：显式执行 `test:soak`，两个浏览器同时各运行至少 10 分钟；轮流显示三个图表，记录每 30 秒更新频率与 GC 后的堆和缓冲区内存，并验证停止后所有测试音频上下文关闭、停止采样。结果在 `.local/soak-results/`。
- UI 截图与失败 trace 在 `test-results/`；这些生成物不属于源代码。

自动化的合成输入测试不能替代真人麦克风验收。真实长音、滑音、不同元音、设备音效和实际端到端延迟，需要在目标麦克风上人工确认。

## 代码维护

`src/App.tsx` 负责工作区与共享显示状态；`src/components/Charts.tsx` 负责三个 Canvas 图表和音高曲线；`src/components/Piano.tsx` 为参考键盘。样式位于 `src/style.css`。

```powershell
npm run format
```

第一版不包含录音保存、音频文件导入、系统音频采集、测验评分、和声识别或桌面安装包。
